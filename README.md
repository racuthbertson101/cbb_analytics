# CBB Analytics

A personal Division I men's college basketball ratings, statistics and prediction site (think KenPom + EvanMiya + Sports Reference, with team logos and a dark, chart-heavy UI). Everything is generated by a Python pipeline and published as a static Next.js site; nothing runs on a server.

Read `SPEC.md` for the original brief, `PROGRESS.md` for build status, `DECISIONS.md` for every judgment call, `KNOWN_ISSUES.md` for limitations and `FINAL_REPORT.md` for the summary.

## What you get

- **Today**: every game on a date with predicted score, win probability (80% interval), a 1-10 watchability score with a visible breakdown, and result-versus-expectation once played. `?asof=YYYY-MM-DD` replays any past date.
- **Rankings**: adjusted efficiency, consensus, margin-aware Elo, Bradley-Terry, player-driven and mean-rank systems, plus a résumé view (wins above bubble, strength of record, quadrant records, SOS). Season and as-of-date selectors.
- **Team / Player / Game-level pages**, **Conferences** (strength, non-conference results, projected standings from 20,000 simulations with each conference's own tiebreaker rules), **Accuracy** (append-only prediction log plus walk-forward backtest), **Compare** (any two teams and a site), **Methodology** (every fitted parameter and validation result, generated from `pipeline/params/`), **Search** (Ctrl/Cmd+K) and a **Tournament** placeholder.

## Quick start (local)

Requirements: Python 3.11+, [`uv`](https://docs.astral.sh/uv/), Node 20+, `git`, and the GitHub CLI `gh` (only for publishing).

```bash
uv sync                    # python dependencies
make backfill              # download bulk data (sportsdataverse releases) and build the warehouse
make ratings               # fit every model and write pipeline/params (about 35-40 minutes, one time / after each season)
make site                  # export JSON shards into web/public/data and build the static site into web/out
cd web && npx next dev     # or open web/out with any static server
make test                  # unit tests (leakage, tiebreakers, warehouse validation, ...)
```

Replay the whole nightly path as if it were a past date (the season is not running, so this is how you see an "in season" night):

```bash
make replay DATE=2026-02-15   # ingests from ESPN with results on/after DATE masked, refits, predicts 7 days, simulates, exports
make site                     # restores the normal (last completed season) site afterwards
```

## Publishing to GitHub Pages (one-time setup)

The build environment could not create the public repository for you, so these steps are yours:

```bash
gh repo create cbb_analytics --public --source=. --remote=origin --push
gh api -X POST repos/:owner/cbb_analytics/pages -f build_type=workflow      # enable Pages with GitHub Actions
gh api -X PUT repos/:owner/cbb_analytics/actions/permissions/workflow -f default_workflow_permissions=write -F can_approve_pull_request_reviews=false
uv run python -m pipeline.release upload                                     # publish warehouse + artifacts to the `warehouse` release
gh workflow run deploy.yml                                                   # first deploy
gh workflow run nightly.yml                                                  # then the full nightly path (manual dispatch)
```

The site will live at `https://<your-user>.github.io/cbb_analytics/` (`basePath` is `/cbb_analytics`, set through `NEXT_PUBLIC_BASE_PATH`; every fetch goes through `dataUrl()` in `web/lib/data.ts`). Record the live URL in `PROGRESS.md`.

## Automation

| Workflow | When | What |
|---|---|---|
| `nightly.yml` | 07:30 UTC daily + manual | download warehouse/artifacts, ingest new games from ESPN (rechecking 3 days), validate, refit the live season with stored parameters, predict the next 7 days, append to the prediction log, simulate conferences, export JSON, build, deploy, upload updated data. Full run Nov 1 - Apr 15, light weekly run otherwise. Any failure stops before deploy, so the previous site stays up. |
| `refit.yml` | manual | re-estimate every hyperparameter and artifact (`make ratings`), commit refreshed `pipeline/params/`. Run once after each season. |
| `deploy.yml` | manual | republish from stored data without ingesting. |

## Repository map

```
pipeline/ingest      bulk downloader, ESPN incremental client, audit
pipeline/warehouse   table build, validation, paths
pipeline/models      adjusted efficiency (ridge), backtest, Elo, Bradley-Terry, résumé, consensus, watchability, registry
pipeline/players     player season lines, impact rating, prior evaluation, player-driven team rating
pipeline/sims        tiebreaker engine, conference Monte Carlo, config generator
pipeline/tournament  bracket schema + simulator stub
pipeline/export      JSON writers (data contract), accuracy, systems, players, conferences
pipeline/params      fitted parameters and validation evidence (committed)
config/              watchability.yaml, tiebreakers/*.yaml
web/                 Next.js app (static export), config/site.json = nav tabs and ranking-system toggle
docs/                DATA_CONTRACT.md, METHODS.md, EXTENDING.md
```

## Honest caveats

See `KNOWN_ISSUES.md`. Highlights: player impact is a v1 box-score model; 12 of 31 conferences use fallback (not verified) tiebreaker text; the margin-aware Elo is about as accurate as the ridge model on margin; no live season has been observed yet, so the Accuracy page's live scoreboard starts empty.
